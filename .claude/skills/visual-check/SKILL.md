SVG 生成コードの変更は実際に描画しないと破綻に気づけない（例: クローズアップで髪型が破綻していた事例）。また、破綻なく描けていても初見の子どもに伝わらないことがある（観察メモ 2026-07-13: figure が題・凡例の欠落で「意味不明」——G9 は通過していた）。**エンジン描画コードの変更時だけでなく、シーン地図・figure・closeup のデータを新規執筆・変更したときも**このスキルでレンダリングして確認する。

## レンダリング

出力先はスクラッチパッド（一時ディレクトリ）を使う。

- **似顔絵を変更した場合**（`src/engine/art/face.ts`・`src/works/hidenaga/faces.ts`）:
  `npx vite-node scripts/render-faces.ts <出力ディレクトリ>`
  全人物のコンタクトシートが出力される。各人物は「大170px円（鑑賞品質）／52px円／52px正方形（カード実寸の判別性）」の3態で並ぶ。大きい表示だけでなく**カード実寸での判別性**も確認する。
- **シーンビジュアルを変更した場合**（`src/engine/map/sceneMap.ts`・`src/engine/art/closeup.ts`・`src/works/<作品>/map.ts`・story の `closeup`/`figure` 指定）:
  `npx vite-node scripts/render-scene.ts <出力.svg> [章] [シーンid] [work-slug=hidenaga]`
  例: `npx vite-node scripts/render-scene.ts /tmp/scene.svg 7 7-a2`
  シーンが `closeup` を持てば対面の場、`figure` なら人の図、なければ読み解き地図が出力される（SceneScreen と同じ選択規則）。変更が複数シーンに影響する場合は、影響するシーンをすべてレンダリングする。
  **出力は自己完結 SVG**（`scripts/lib/static-css.ts` が var()/color-mix() をライトテーマの literal に解決し `.scene-map` スタイルを埋め込む）なので、**`rsvg-convert -w 900 <svg> -o <png>` でそのままラスタ化して自分の目で確認できる**（旧「rsvg では地図の色・ルート線が落ちる」制約は 2026-07-13 に解消）。未確認のまま残るのはアニメの動き・ダークテーマ・DOM の hover/tap のみ。ブラウザ向けと同一のエンジン出力を見たいときは `--raw`。

## 確認

1. **自分でラスタを目視する**（`rsvg-convert` で PNG 化して Read で見る）。テキスト同士・テキストと矢印/アイコンの重なり、色の破綻、はみ出しは座標の数値点検では見逃す（off-map 矢印がラベルの縁取りに塗り潰されていた実例＝2026-07-13 検出）ので、必ず画像で見る。
2. **初見読解の self-check（破綻がないか、に加えて）**: 本文を知らない初見の子どもがこの絵から何を読み取るかを、先に自分の言葉で書き出してから本文・シーンの核と突き合わせる。題・凡例・note が核と整合しているか、誤読の余地（主語の曖昧な note・cur 顔の直下に他者の行い・既有文法との衝突）がないかを見る。核が読めなければ破綻ゼロでも直す。新規執筆の主ビジュアルは `/eval-work` のビジュアル読解ペルソナ（画像だけを見せる別エージェント）でも検査される——self-check はその前段の一次防衛線。
   - **シーン地図は「入口の状況」にアンカーしているか**: 判定＝「このシーンで読者が最初に立つ場面は地図に表れているか／地図はまだ読んでいない先の結末に飛んでいないか」。原則・例外（むすび・reveal・臨終の山場は結末を見せてよい）と他の地図規律は docs/WRITING.md「地図・図の書法」。
3. SVG ソースも読み、明らかな異常（要素の座標が枠外、NaN、空の path）がないか確認する。
4. attended run では、生成した SVG/PNG を SendUserFile（`display: render`）でユーザーにも送り目視確認を依頼する（無人ループでは応答が返らないので送らない）。
5. 破綻が見つかったら修正して再レンダリングし、比較できるよう修正前後の両方に触れて報告する。
