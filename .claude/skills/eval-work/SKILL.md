作品コンテンツの変更を docs/CRITERIA.md に照らして評価する。

## 手順

1. **対象の特定**: 評価対象（差分、または指定された章・シーン群）を特定し、本文・選択肢・Hist・deep・カード等の評価対象テキストを抜き出す。docs/VISION.md・docs/CRITERIA.md・**docs/WRITING.md（執筆規律＝執筆面の実務規準）**を読む。
   - **機械測定を先に**: `npx vite-node scripts/content-stats.ts <slug>` を走らせ、WRITING.md 予算表との比較を評価対象テキストに添えて各エージェントへ渡す（予算超過は `tests/style-budget.test.ts`＝G2 の fail として現れる。EXEMPT 章でも実測値は判断材料として渡す）。
   - **ビジュアル在庫レポート**: `npx vite-node scripts/visual-coverage.ts <slug>` を走らせ、主ビジュアル未執筆（フォールバック地図のまま）のシーン一覧を報告に添える。fail 条件ではない（執筆中作品は未執筆で正常）——「壊れていないから見えない」を可視化するのが目的（観察メモ 2026-07-13 根本原因 (B)。完成作品の回帰は `tests/visual-coverage.test.ts` が機械で fail させる）。
   - **対照シーンの用意**: hidenaga から同種のシーン（同じ役割: 章開幕・岐路・むすび等）を1つ抜き、ペルソナの比較対照として渡す。hidenaga は子どもの実反応で検証済みの基準コーパス。
2. **多角評価（Workflow）**: Workflow ツールで以下の観点を並列エージェントとして走らせる。各エージェントには評価対象テキストと該当する CRITERIA 項目を渡す。各エージェントは既定で **`{model:'sonnet', effort:'medium'}`** で走らせる（読者シミュレート・監査は sonnet で十分。並列本数ぶんモデル差の節約が効く）。品質の防止線である**反証ステップだけ例外的に強モデル**にする:
   - **ファクトチェック**（G5・S-D）: WebSearch で通説・研究と突き合わせ、指摘には出典を付ける。指摘ごとに反証エージェント（「この指摘は本当に誤りか？諸説の範囲に収まらないか？」）を1回通し、反証に耐えた指摘のみ採用する。反証エージェントは **`{model:'opus', effort:'high'}`**（誤指摘の採用を防ぐ最終線）。
   - **小5ペルソナ読者**（G8・S-C1・S-A）: 10歳の読者として読む。**読了義務なし**——ゲーム機も漫画も手の届く所にある前提で、飽きたらそこでやめ、**やめた段落と理由を必ず報告**する（最後まで読んだならそう報告）。読めない語・つまずく文・「なぜ？」と思えた箇所も列挙。**対照シーン（hidenaga）と比べ「どちらを読み続けたいか」**を答える。
   - **中1ペルソナ読者**（S-C2・S-A）: 13歳の読者として同様に読む（読了義務なし・離脱点報告・対照比較は小5と同じ）。幼稚に感じた箇所・「もっと深く」の物足りなさ・面白かった箇所を列挙。
   - **離脱の扱い**: いずれかのペルソナが**最初の選択肢・ミニゲーム到達前に離脱**したら S-A は3点未満（＝マージ不可要因）とする。対照シーンに明確に負けた（両ペルソナが hidenaga を選んだ）場合も S-A は3点以下から始める。
   - **ビジュアル読解ペルソナ（伝わるかゲート）**: 評価対象に**主ビジュアルの新規・変更**（closeup / figure / シーン地図）が含まれるときだけ実施する。`npx vite-node scripts/render-scene.ts <out.svg> <章> <シーンid> <slug>` → `rsvg-convert -w 900 <svg> -o <png>` で PNG 化し、**画像だけ**（本文・シーン名・意図は渡さない）を初見の小5相当ペルソナ（`{model:'sonnet', effort:'medium'}`）に見せて「この絵から何が分かる？ だれが・どこで・何が起きている？」を自由記述させる。回答をシーンの核（1シーン1絵1感情）と突き合わせ、**核が読み取れていなければその装置は fail**（題・凡例・note・構図を直して再評価。破綻がなくても伝わらなければ fail——観察メモ 2026-07-13「figure が意味不明」は G9 通過後に起きた）。vision トークンは高いので対象は変更分の主ビジュアルに限り、ペルソナは小5のみを既定とする（読解の床は小5。確度マーク等、中1向け情報を載せた装置のみ中1を追加）。
   - **VISION 監査**（G6・G7・S-B）: 英雄化・説教・敵役の平板さ（善悪の垣根）、断定と創作の混同、アンチゴール抵触を監査する。
3. **採点**: 各エージェントの結果を CRITERIA の G ゲート・S 項目に対応づけ、根拠1〜2文つきで採点する。
4. **報告**: 次の形式でまとめる:
   - G ゲート: pass / fail（fail は箇所と理由）
   - S 項目のうち 3点未満（マージ不可要因）と 4点未満（改善候補 → BACKLOG「未整理」へ追記）
   - ペルソナの離脱点（離脱があった場合）と対照比較の結果
   - ビジュアル読解の結果（実施した場合: ペルソナが読み取った内容とシーンの核とのズレ）と、ビジュアル在庫レポートの未執筆シーン数
   - 直すべき箇所の具体リスト（優先順）
   - **傾向ルール**: **S-A 系の4点未満が2章連続**したら、報告に「体験の漂流」と診断（何が足りないか・対照比較の逐語を根拠に）を明記し、**次章に織り込む宿題**として BACKLOG の当該章タスクに書く。執筆は止めない（体験の不足は書いて実測しないと直らない）。**着手不可にできるのは 3点未満だけ**（＝CRITERIA のマージ基準）。
5. **再評価は差分駆動で打ち切る（トークン規律）**: `/auto-dev` から呼ばれて修正→再評価するときは、**その修正が影響する軸だけ再走**する（本文→小5/中1ペルソナ＋VISION監査、事実→ファクトチェック〔反証込み〕、ビジュアル→読解）。無関係な軸は結果が変わらないので再走しない。**最大2ラウンド**で G fail・S<3 が消えなければ、コミットせず人間に報告する（暴走天井）。

## 注意

- ペルソナ読者は代理指標にすぎない。BACKLOG「観察メモ」（人間が書く子どもの実反応）と矛盾したら人間の観察が優先。**特に「退屈・引き込まれない」は LLM ペルソナが最も検出を苦手とする軸**（第2作で全章 eval 通過後に実プレイで発覚した——docs/WRITING.md「成立の経緯」）。だからこそ読了義務を外し・対照比較で測り・機械予算で下限を張る。絶対採点は4点に飽和しやすいので、迷ったら対照比較の結果を優先する。
- G9（描画の破綻）は本スキルの対象外 — `/visual-check` で別途行う。ただし**「破綻なく描けているが読者に伝わらない」**は本スキルのビジュアル読解ペルソナが担う（破綻チェックと読解チェックは別物。観察メモ 2026-07-13: figure は G9 通過済みなのに実プレイで意味不明だった）。
- 評価対象が大きい（複数章にまたがる）ときは章ごとに分けて実行する。
- 無人ループでは eval-work がコミット間の唯一の自動品質ゲート。ペルソナ/監査は sonnet に落としてよいが、**反証ステップは強モデルを保つ**——品質の劣化がサイクルをまたいで累積しないようにする。
