# 作品間の連携 — 同一人物の橋（確定設計）

2026-07-25、人間と対話で確定。起票は docs/BACKLOG.md「作品間の連携」1。
狙いは VISION 大目標2（善悪の垣根を超えた人間理解）を**説明でなく並置で**成立させること
——同じ人物が、遊ぶ作品によって違う顔で現れる。副次で大目標1（次の作品への内発的動機）。

## 1. 素材の実測（2026-07-25 時点）

作品横断で同一人物なのは、顔もカードも id が完全一致する **4組だけ**（名前一致で id 違いのケースはゼロ＝id 体系は既に一貫している）。

| base pid | 作品 | 状態 |
|---|---|---|
| `p-hideyoshi` | hidenaga ↔ ieyasu | 出荷済み |
| `p-nobunaga` | hidenaga ↔ ieyasu | 出荷済み |
| `p-yoritomo` | kiyomori ↔ masako | 出荷済み |
| `p-yoshinobu` | katsu ↔ shibusawa | 渋沢の出荷待ち |

教材価値の裏づけ＝同じ `p-hideyoshi` のカード本文:

- hidenaga「秀長の 兄。……**弟に「侍に なれ」と 声を かけた 張本人**」
- ieyasu「妹を とつがせ、母までを 人質に 出して、**きみに 頭を 下げさせた**。——そして きみは、この 男の 死後、その 遺児と 豊臣家を ほろぼす。**きみの 一生 最大の 割り切れなさ**」

並べるだけで視点が相対化される。地の文の説明は不要——というより、説明したら台無しになる。

## 2. 名寄せをどこが持つか

**works 層に allowlist 1枚**（`src/works/` 直下。`registry.ts` と同じ「作品集の層」）。キーは **base pid**。

- engine に置けない（固有名詞のハードコード禁止＝CLAUDE.md 分離原則）。engine には型だけ置き、アプリ層が表を読んで context で配る。
- 作品データ側に `alsoIn` を書くと作品が他作品を知る＝依存が組合せで増える（6作で15組）。表なら1枚。
- **allowlist にする理由（実測で判明）**: ①id 偶然一致の別人事故を弾ける ②**表記揺れを吸収できる**——`p-hideyoshi` は hidenaga で「羽柴秀吉」、ieyasu で「豊臣秀吉」。id 一致の自動照合では「名前が違う＝別人では？」を判定できない。逆に表があれば、**改姓それ自体を素材にできる**（出世で姓が変わるのは当時の常識＝子どもには驚き）。
- 顔の一致は `tests/face-distinct.test.ts` の `crossWorkInconsistencies` が既に強制済み（同 pid は造作一致・tone だけ陣営色として可変）＝**名寄せの半分は既に存在する**。
- 表のキーが base pid なのは、顔が `@old` 等の variant を持つのにカード id は base のみだから（政子の物語に出る清盛は晩年＝variant が変わる）。variant の扱いは face-distinct の既存契約に任せる。

### テスト（新設）

- 表の各組について、当該 person カードが**両作品に実在**する。
- **表に無いのに複数作品に同 id の person カードがある → fail**（新規の偶然一致、または起票漏れの検出）。

## 3. 何を見せるか（強度＝本文の並置）

`src/engine/ui/overlays/CardModal.svelte` に橋ブロックを1つ。`Account.works[作品id].cards`（`src/engine/save.svelte.ts`）で相手作品の取得状態が分かるので3態:

| | 条件 | 出すもの |
|---|---|---|
| A | 相手作品でも**そのカードを取得済み** | 相手のカード本文をそのまま並置（名前が違えばそれも見せる） |
| B | 相手作品を遊んでいるが**未取得** | 何も出さない（先食い防止） |
| C | 相手作品を**未プレイ** | 誘い一行「この人は『政子』にも 出てくる」 |

**相手作品の本文の読み方**: 配信はチャンク分割で他作品は遅延 `load()`。表に本文を焼くと二重管理になる（`engine/graph.ts` のヘッダが戒める「同じ事実を2箇所に持つと、いつか食い違う」）ので、**A のときだけ `registry[wid].load()` で動的に読む**。C の誘い一行は人物名（自作品側）＋作品名（軽量 `WorkCard`）で足りる＝**ロードゼロ**。

tone は作品ごとの陣営色なので、並置すると同じ人物の顔の色が変わる。挙動としては正しい（陣営が違う）が「別人に見える」危険があるため `/visual-check` 必須。

### S1 実装で確定したこと（2026-07-25・実ブラウザで検証）

- **相手の顔は出さない**。上の tone の危険を、そもそも顔を二度描かないことで回避した（並置の火力は本文にある）。
- **二人称のアンカーが要る**。相手の本文は相手の読者に向けて書かれており（『政子』の頼朝＝「きみの 夫」）、ただ並べると「きみ」がこちらの主人公を指す。ラベルを **「きみが 『◯◯』だった なら」** にして繋ぎ直した（説明ではなく文法。作品名＝主人公名に乗っている）。
- **橋は本文の直下・写真の上**。写真をはさむと別々の話に見える＝並置は隣り合っていて初めて効く。
- 名前が同じ相手（頼朝）は名前行を出さない。違えば名前＋ふりがな（`Card.read`）を出す＝改姓それ自体が素材。

## 4. 在庫を増やす（S2）

現状3組は**すべて脇役どうし**で、**主人公が他作品に出る橋はゼロ**。『政子』の頼朝カード本文には「平清盛」がルビ付きで出てくるのに、清盛のカードも顔も無い＝**『清盛』を一生ぶん生きた子が、『政子』で清盛に再会できない**。

この装置の最大火力は「きみが一生を生きたあの人が、こんどは他人の物語の脇役として現れる」。脇役カード1枚＋顔1つで作れる（章本文に組み込むなら重い）。

- **清盛 → masako**: 頼朝を助命した人＝政子の物語の起点（清盛が殺していれば、政子は夫に出会っていない）。
- **秀長 → ieyasu**: 1586 の上洛で家康が泊まった屋敷の主＝家康が頭を下げる章（ch4）の裏方。

いずれも faces は base 造作一致が必須（tone は可変）。史実の詰めと本文は `/eval-work` 対象。ダ・ヴィンチは世界史ゆえ構造的に孤立（橋なし）。

### S2 実装（2026-07-25）

- **秀長 → ieyasu ＝実装済み**。カード `p-hidenaga`（ch4・tone gold）＋顔（hidenaga の代表顔とバイト一致）＋**4-c で付与**。4-c は元から「宿は、秀吉の 弟・秀長の 屋敷だ」と**名前だけ出して**いた——WRITING §5「名前だけの人物を出さない」の未回収が、橋の置き場所とちょうど重なった。**橋を架ける先は、既に名前だけで通り過ぎている人を探すと見つかる。**
- **相手が主人公だと S1 のアンカーがそのまま効く**。相手作品の本文は「きみ 自身。大和大納言…」で始まり、ラベル「きみが『豊臣秀長』だった なら」に続けて読める＝主人公カードは**二人称の座標系を明示的に持っている**ぶん、脇役カードより並置に強い。
- **相関図には載せない**。あの輪は主人公自身の縁の図で、既存カテゴリ（渡り歩いた主君／敵／家族／家臣／神にした人）のどれに入れても史実が歪む。**橋のカードは図鑑には出るが輪には出ない**——これを S2 の既定にする。
- **⛔ 清盛 → masako は止まっている**。masako は人物カード 16人＝WRITING「人は絞る」の上限ちょうどで、17人目にするか誰かを落とすかは体験予算の緩和＝人間判断。**橋の在庫は「相手作品に空き枠があるか」で決まる**——設計時に相手の人数を見ておく。

## 5. やらないこと

- **橋をコレクション対象にしない**（VISION アンチゴール「学びと切れた報酬」）。集めた数を数えた瞬間に、報酬のための報酬になる。
- **地の文で「同じ人でも見え方が違う」と説明しない**。並置だけで語らせる。
- カードの取得は引き継がない（作品ごとに別枠のまま）。目的は時代が地続きだと分かること。
