# 設計調査 — 顔画像生成エンジン（face-engine）

> **位置づけ**: 観察メモ（2026-07-16・(3)「顔のバリエーションを増やしたい。大きな工数を割いて良い」）への**第1スライス＝設計調査**。以後のスライスは**章執筆と交互**に進める（本線＝家康を止めない）。
> **要件（観察メモの逐語から）**: ①今後の作品増に耐えるバリエーション生成 ②有名な歴史的人物は世間のイメージを壊さない絵。
> **⚠️ 2026-07-17 人間指示による改訂**: 「既存の顔（家族が覚えた顔）は変えない、という判断をしたようですが、**変えてください**。むしろ、**制約なしに理想の顔エンジンを作って、作品全体のクオリティ向上を第一に**してほしいです」（観察メモ逐語）。→ 本文書の「既存顔バイト不変」の互換既定（旧 §3-3・旧 §7-2）は**撤回**。出荷済みの顔も品質のために自由に変える（変更は REVIEW で告知＝判断待ちでなく報告）。単一 HTML・`<defs>`/id 禁止・決定的生成などの**アーキテクチャ制約は対象外**（人間が撤回したのは互換凍結だけ）。
> **拠り所**: `src/engine/art/face.ts`（生成器）・`src/works/*/faces.ts`（作品データ）・`scripts/face-audit.ts`（本調査で新設した重複計測）・VISION 原則4「人物は声と信条で刻む」（顔は「一目で見分けられる」ための装置＝hidenaga faces.ts ヘッダ）。

## 1. 現状の棚卸し（エンジンのパラメータ空間）

顔1体は `FaceSpec` の14フィールドで決まる（`src/engine/types.ts`）。数値の口は無く、**色2つ（skin/iris＝自由 hex）以外はすべて離散キー**。座標・寸法は face.ts 内の 100×100 座標系にハードコード。

| 部品 | フィールド | 実装分岐数 | 備考 |
|---|---|---|---|
| 髪・かぶり物 | head | **16**＋基本髪 | 現行の語彙は face.ts の `HEAD_KINDS`（`tests/face-vocab.test.ts` が実装と突き合わせる）＝eboshi/kanmuri/chasen/kabuto/bozu/zukin/ama/onna/suberakashi/chonmage/sangiri/seibo/nanban/wakamusha/maegami/beret |
| 輪郭 | shape | 5 | oval(既定)/round/long/square/gaunt |
| 目 | eye | 8 | calm/sharp/gentle/closed/narrow/lively/cry/wide |
| 口 | mouth | 6 | smile/grin/flat/frown/soft/laugh |
| 眉 | brow | 5 | calm/soft/stern/angry/worried |
| ひげ | beard | 4 | 無し/beard/mustache/full |
| **鼻** | （無し） | **1** | 固定1種（noseArt に分岐なし）＝**最大の空白** |
| 頬 | cheek | 4 | 無し/monkey/blush/sunken |
| 耳 | ears | 2 | 標準/big |
| 年齢演出 | age | 3 | 無し/old(しわ)/child(大瞳) |
| 衣・襟 | garb | 3 | kimono(既定)/western/navy |
| 髪色 | hair | 3 | dark/grey/white（パレット固定） |
| 衣の色 | tone | 5 | ai/gold/seal/midori/ink（**陣営色**＝作品ごとの関係軸。造作ではない） |
| 肌・虹彩 | skin/iris | 連続 | 自由 hex。影・線は `color.ts mixHex` で決定的に派生 |

- 組合せは理論上 数千万通り。だが **知覚上の識別はこの掛け算では決まらない**（§2）。
- 描画制約: `<defs>`・id・`url(#…)` 禁止（複数顔を1 SVG に転記するため）。グラデーション不使用。単一 HTML ビルドと整合。
- 消費先: 地図マーカー・カード図鑑・closeup（バストアップ合成）・相関図・人の図・人生ステージ1枚絵。**すべて同じ `faceArt()` の出力**＝生成器を直せば全面に効く。
- G4 監査: エンジン本体（face.ts/closeup.ts/color.ts）に作品固有の定数・人名の実コード混入なし（コメントのみ）。唯一 `scripts/render-faces.ts` の CLI 既定 slug `'hidenaga'` が作品固有（開発ツールの既定値であり動作影響なし・低優先）。
- 作品側の運用装置（既に確立・維持する）: 章別の加齢差し替え `PROTAGONIST_FACE_BY_CH`・感情の山場の `SCENE_FACE_OVERRIDES`（`@grief` 等）・人生ステージ1枚絵 `PROTAGONIST_STAGES`。

## 2. 重複の実測（`scripts/face-audit.ts`・2026-07-17）

観察メモ「既に作品間で似た・同じ画像が使われてしまっている」を機械計測に落とした。造作13フィールド（tone 除外・省略値は既定値に正規化）のハミング距離で、**別人どうし**のペアを数える（同一人物の加齢/感情派生・作品間の同一人物は除外）。対象 74 specs・52人・4作品。

| 距離 | ペア数 | 意味 |
|---|---|---|
| **0** | **1** | **完全に同じ絵**: hidenaga 藤堂高虎 ⇄ kiyomori 平知盛（tone まで同一 'ai' ＝ピクセル同一）。観察の「同じ画像」の実体 |
| 1 | 15 | 1部品差。**同一作品内にも存在**: katsu 勝⇄小栗（目だけ）・勝⇄鉄舟（輪郭だけ）。作品間では子ども顔クラスタ（秀長@child⇄清盛@child⇄安徳）が典型 |
| 2 | 47 | 2部品差。カード図鑑 52px 実寸では見分けが怪しい帯 |

使用分布の偏り（74 specs 中）: 鼻 **74全員が同一**・mouth flat 40・hair dark 61・iris 既定 66・ears/cheek/age/garb は大半が既定。

**構造的な原因**: 識別チャネルの実効数が時代・身分・年齢で焼き尽くされる。head は時代でほぼ決まり（katsu は14人中10人が chonmage）、hair は年齢で、brow/mouth は人柄で決まる——**自由に振れるのは実質 shape(5)×eye(8) 程度**で、同時代・同身分・同年代の人物はすぐ衝突する。作品が増えるほど同じ時代帯（戦国×2作品目が既に発生）で衝突が加速する。これが観察メモの指摘の機序。

なお**同一人物の作品間 drift は 0**（信長・秀吉は hidenaga⇄ieyasu で造作が一致）＝設計原則「作品間で人物を矛盾させない」は守られており、本エンジンでも維持する。

## 3. 要件の翻訳（観察メモ → 設計目標）

1. **バリエーション**: 新作品1本（人物 12〜16人）を追加しても、既存全人物との距離 ≥ 2 を保てる語彙量。時代を共有する作品（戦国は既に2作）でも枯れないこと。
2. **有名人物の通説イメージ**: 教科書肖像・大河等で子どもが既に持っているイメージと衝突しない（§5 の典拠方針）。
3. ~~既存顔の互換~~ → **品質第一（2026-07-17 人間指示で置換）**: 既存顔は凍結しない。出荷済みの顔も作品全体のクオリティのために変えてよい（変更は REVIEW で告知）。ただし**同一人物の作品間一致**（信長・秀吉が hidenaga⇄ieyasu で同じ顔）は品質そのものなので維持し、`tests/face-distinct.test.ts` が機械で守る。
4. **ランタイム制約の維持**: 単一 HTML・外部アセットなし・`<defs>`/id なし・実行時外部依存ゼロ。
5. **検査可能性**: 「似すぎ」を目視でなく機械で検出できること（face-audit のゲート化）。

## 4. 設計案の比較と推奨

- **案A: 離散プリセットの増設のみ**（鼻3種・眉太さ等を足す）——最小工数だが、チャネルあたり数個の追加では2〜3作品でまた枯れる。②に直接は効かない。**単独では不足**（ただし案Cの一部として実施）。
- **案B: 画像生成 AI による事前生成ラスタの焼き込み**——base64 PNG は1顔 20〜50KB×50人超で単一 HTML が MB 級に肥大。手描き SVG の学習まんが調と混在して作品の絵として割れる。生成のたびに絵柄が揺れ、同一人物の作品間一貫性・G9 検査・後からの微修正（1フィールド直すだけ）が全滅する。**不採用**。SVG spec の下書きに生成 AI を使うのは可（人が spec に清書して初めて取り込む＝データは静的手書きのまま）。
- **案C: パラメトリック連続化＋離散増設のハイブリッド（採用・スライス2で稼働）**。
  - **C-1 連続 morph パラメータ**（実装済み・スライス2）: `FaceSpec.morph` に `eyeY`/`eyeScale`/`browY`/`mouthY`/`mouthScale`（レンジは types.ts の `FaceMorph` に文書化・テストが強制）。**実装は部品ごとの `<g transform>` ラップ**——部品アートのパス文字列は無改変のまま、目=中心(50,52.5)基準のスケール＋平行移動・眉/口=平行移動＋幅スケール（口ひげは口と同一グループ＝離れない）。パスを書き換える座標リファクタより安全で、決定的・検査可能。省略時は従来座標（互換の保証ではなくデータ経済＝74 specs を書き直さないため）。連続チャネルは離散と違い「時代・身分で焼き尽くされない」。残チャネル（顔幅 `faceW`・目の間隔 `eyeGap`・眉角度 `browTilt`）はパス書き換えが要るためスライス4へ。
  - **C-2 離散の空白を埋める**（鼻=実装済み・スライス2）: `FaceSpec.nose` = tall/round/thin/wide の4種＋既定。次いで眉の太さ、たれ目/つり目の中間段（スライス4）。
  - **C-3 識別性ゲート**（実装済み・スライス2）: `tests/face-distinct.test.ts`——**別人どうしが距離 ≤ 1 なら赤**（morph は量子化して距離に算入・tone 除外）＋作品間 drift 検査＋nose 語彙/morph レンジ検査（打ち間違いは黙って既定にフォールバックするため）。既存の衝突16ペア（距離0〜1）は**ゲート化と同時に造作調整で解消済み**——EXEMPT リストは作らなかった（凍結は「予算緩和と同型の穴」）。
  - **C-4 決定的ジッター（保留・最後のスライス）**: 手書きが省略した連続パラメータを hash(人物id) から導く案。工数最小で全員が微差を得るが、「顔の意図」が乱数に散り、有名人物の通説イメージ（§5）と衝突しうる。**C-1〜C-3 の実測後に必要性を再判定**する（YAGNI）。

## 5. 有名人物の肖像典拠方針（要件②）

「世間のイメージ」は気分でなく**典拠を3層で言語化**して faces.ts のコメント（既存の流儀）と research に固定する:

1. **教科書・肖像画の通説イメージ**——ただし肖像自体の帰属論争（伝源頼朝像＝足利直義説、「信玄像」の帰属諸説＝ieyasu faces.ts で既に注記済み）も併記する。**肖像の諸説はこのプロジェクトでは隠す対象でなく教材資源**（VISION 原則6）。
2. **大河・マンガ・ゲームの支配的イメージ**——子どもの既知はこちらが形成している場合が多い（ただし観察メモ 2026-07-16 の教訓: ポップカルチャーの知名度を過信しない。「既知のはず」は観察で裏切られる）。
3. **史料に残る風貌記述**——例: 秀吉の「猿」（既に実装: ears:big＋cheek:monkey）、家康の肥満（しかみ像の帰属諸説も §1 と同型）。

運用: **research/<作品>.md に「風貌・肖像典拠」節を設け、主要人物ごとに「外せない特徴（かぶり物・ひげ・体格・表情の4点）」を書いてから faces.ts を書く**。ieyasu では事実上実施済み（faces.ts の各行コメント）——これを新作品の必須手順に格上げする（企画の章カルテと同じ「書く前に決める」規律）。有名度が低い人物（記録なし）は自由造形＝ジッター許容域。

**★davinci で初の明示実施（2026-07-19・research §4B）**: 距離フロア（要件①）は slice 8 で密帯に到達し限界効用が低下したが、**忠実さ（要件②）は別軸で未着手だった**——本節の手順を davinci で初めて明示的に実施した。学び: **有名人物の「顔の通説」は肖像の帰属論争を伴うことが多く（レオナルド自画像☆・チェーザレ肖像☆＝メローネ同定は伝承）、§3 の史料批判（伝記の脚色）と同じ構造が肖像にもある**＝忠実さは「確定肖像を写す」でなく「通説像を採用しつつ伝承である度合いを確度で正直に記す」。ファクトチェックが実データの**史実誤り**も検出した（ルドヴィコ「イル・モーロ」を色白丸顔で描いていた＝あだ名〔浅黒い肌〕と正反対→浅黒い面長へ補正・フランソワ1世の鼻を wide→tall〔大鼻王〕）＝**距離ゲートは別人性しか守らず、通説イメージへの忠実さは典拠でしか担保できない**（要件②の機序）。要件②は新作品ごとに繰り返す手順で、フロア引き上げのような corpus 全体の逓減はない。

## 7. 確定した判断（次スライスの前提）

1. ラスタ生成（案B）は不採用——単一 HTML・絵柄一貫・検査可能性の3点で SVG パラメトリックに劣後。
2. ~~互換の既定は「既存 spec の描画バイト不変」~~ → **2026-07-17 人間指示で撤回**。品質第一・既存顔も自由に変える（REVIEW で告知）。同一人物の作品間一致だけは維持（テストが強制）。
3. 鼻が最大の空白（74人同一）→ **スライス2で解消**（4種追加・主役級と衝突ペアに配布済み）。
4. 識別性の本丸は連続チャネル（時代・身分で焼き尽くされないため）→ morph 5チャネル稼働。実装は transform ラップ＝パス無改変（スライス2の学び: 安全に漸進できる）。
5. tone は造作でない（陣営色）——重複判定から除外し続ける。高虎⇄知盛のような「tone も造作も同一」が真の完全重複（スライス2で解消済み）。
6. 有名人物は「4点チェック（かぶり物・ひげ・体格・表情）＋典拠3層」を書いてから描く。

## 8. 要件③ — 表現域（2026-07-25 の観察メモ②で追加された第三の軸）

> 逐語: 「**女性が女性っぽくない**。全体的に**顔のバリエーションが少ない**ように見えるので、増やしたい。」

要件①（別人距離）②（典拠忠実）とは別軸。①②が満点でも、**描き分けの語彙そのものが足りなければ**この指摘は消えない。

### 8-1 実測（117 spec・7作品）

| 事実 | 数 |
|---|---|
| 女性の顔 | **12 / 117（10%）**。katsu・shibusawa は女性ゼロ |
| 女性の顔のうち `head:'suberakashi'`（垂髪） | **8 / 12** |
| garb が既定（男の着物の襟）の顔 | **108 / 117（92%）**——**女性12人も全員が男と同じ襟と肩** |
| mouth が `flat` | 57（49%） / nose 未指定 55（47%） / hair `dark` 96（82%） |

**機序**: 女性らしさを運ぶチャネルが `head`（髪型）**1本しか無かった**。顔の造作（眉の太さ・輪郭・口）と衣・肩はすべて男女共通で、しかも**この画風でいちばん強い性別の合図＝太い塗りの眉**が全員に付いていた。ゆえに「髪の長い男」に見える。**髪型で稼げないのは史実の側の事情でもある**——平安〜鎌倉の身分ある女性は史実として全員が垂髪で、髪型を作り分けると史実を壊す。だから**識別も性別も、髪型以外のチャネルで稼ぐしかない**。

### 8-2 スライス7でやったこと（engine 2チャネル追加）

- `browWeight:'fine'` — 眉の**太さ**を表情（`brow` の calm/soft/stern/…）から独立させた。実装は `about()` の transform ラップ（スライス2以来の流儀＝パス無改変）。**性別フラグ1個にしなかった**のは、単一フラグは①ステレオタイプの梃子になり②女性全員を同じ顔にする（＝要件③そのものを裏切る）から。太さは男にも使える直交チャネル。
- `garb:'kosode'`（小袖＝なで肩＋広い襟合わせ）/ `'uchiki'`（袿＝襲の色目の重ね襟）/ `'gown'`（16c ヨーロッパの女性の衣＝四角い襟ぐり＋締めた身頃）。**なで肩の肩線**（`shouldersF`）が3種の共通土台。**バストアップでは肩と襟が画面の下1/3を占める**ので、52px でも closeup でも効く。
- 12人へ個別適用（袿7・小袖3・gown 1・尼形の法衣1＝既存の `houe`）。**女性どうしも4種に割れた**（従来は12人とも同じ襟）。
- ゲート: `BROW_WEIGHTS` を `tests/face-vocab.test.ts` に追加（未知値の silent fallback を落とす）＋**「宣言した衣どうしも互いに違う絵になる」**を新設（従来は「既定と違う」しか見ていなかった＝新語彙どうしが同じ絵でも通っていた）。

### 8-3 残（次スライスの候補・実測値つき）

### 8-4 スライス9＝既定値バイアスの配り直し（engine 拡張ゼロ・データ側だけ）

**診断**: §8-3-1 の2数字は engine の語彙不足ではない。`mouth` は6語彙・`nose` は5語彙が既にあり、**どちらも時代・身分・肖像に縛られない自由チャネル**（頭・衣・髪色は史実が塞ぐが、口と鼻は塞がない）。それでも 117 spec の半分が既定値だったのは、**作者が「決めなかった」ぶんが積もった**から。

**やったこと**（7作 横断・engine は1バイトも触らず）:

| | before | after |
|---|---|---|
| mouth | flat **57 (49%)** / soft 30 / frown 17 / smile 6 / grin 4 / laugh 3 | flat **41 (35%)** / soft 39 / frown 23 / smile 6 / laugh 4 / grin 4 |
| nose | 未指定 **55 (47%)** / round 21 / thin 16 / tall 14 / wide 11 | round 36 (31%) / tall 32 / thin 24 / wide 21 / 既定 **4 (3%)** |

残った既定の鼻4つ＝**子ども**（antoku・yoritomo@young・katsu@boy・ieyasu@child）＝katsu が既に書いていた作法（「鼻筋は大人になってから来る」）を corpus 全体の約束に格上げした（清盛の子ども時代の団子鼻だけは一生ものの署名ゆえ例外）。

**ゲート**: `tests/face-variety.test.ts`（新設）＝①最頻値の corpus シェア上限（mouth 38% / nose 34%）②各作品が3種類以上つかう。**自由チャネルだけを見る**——史実が塞ぐ head/garb/hair/age に同じ上限を掛けると、ゲートが史実と戦ってしまう。

**★学び**: 距離ゲート（face-distinct）は**ペアワイズ**なので、この事故を原理的に見つけられない——全ペアが距離を満たしたまま、corpus 全体が単調でありうる。**手癖は分布に出る**ので、分布のゲートが要る。
逆に配り直しは距離を壊す: 同じ「鼻＋口」を2人に与えると新しい衝突が生まれ、実際に8ペアが 2.4 を割った（例＝光秀と三成が「面長・stern・frown・thin」で 2.3、鉄舟が3人と連鎖衝突）。**配り直しと距離は同じループで回す**（audit → 衝突 → 別チャネルで割る、を4周）。鉄舟のように**どのチャネルも既定寄り**の人物が衝突の結節点になり、そこを解くと連鎖ごと解ける。
