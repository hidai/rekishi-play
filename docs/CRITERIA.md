# CRITERIA — 評価ルーブリック

docs/VISION.md の大目標を、チェック可能な基準に落としたもの。作品データ（シーン本文・カード・手がかり・地図等の教材コンテンツ）の追加・変更は、マージ前にこのルーブリックで評価する（実施手順は `/eval-work` スキル）。エンジンのみの変更は G 群（ゲート）だけでよい。

この文書の改訂は人間の承認を要する（AI は改訂案の提案まで）。

## G. must-pass ゲート（ひとつでも落ちたらマージ不可）

| # | 基準 | 判定手段 |
|---|---|---|
| G1 | `npm run check`（svelte-check）が通る | 機械 |
| G2 | `npm run verify`（build＋全テスト）が通る | 機械 |
| G3 | 既存セーブ互換を壊さない（`hidenaga_save_v1` のスキーマ・キー） | 機械（save-compat テスト）＋差分確認 |
| G4 | エンジンに作品固有の定数・固有名詞（動作に影響するもの）を持ち込んでいない | 差分確認 |
| G5 | 歴史記述に明白な誤りがない（人名・年・因果・地理の取り違え） | LLM ファクトチェック（出典つき） |
| G6 | 諸説・不確実な事柄を断定していない（「〜と伝えられる」等の様式を守る） | LLM 監査 |
| G7 | 創作（台詞・内心・場面）が史実と混同されない形になっている（「——気がした」等） | LLM 監査 |
| G8 | 新規・変更シーンの本文の漢字にルビ（`<ruby>`）が付いている | LLM 監査 |
| G9 | ビジュアルに破綻がない（顔が消える・ラベル衝突・はみ出し等） | `/visual-check` の目視 |

## S. 採点項目（各1〜5点）

各項目、根拠を1〜2文添えて採点する。マージ基準は S 合計点ではなく、**3点未満（＝大目標を毀損しうる）の項目が残っていないこと**。4点未満の項目は改善候補として docs/BACKLOG.md に記録する。

### S-A 内発的動機（大目標1）

- A1 選択に「自分ごと」の緊張があるか（正解当てクイズに堕ちていないか）
- A2 非史実選択の「もしも」が面白いか（外した方が得した感があるか）
- A3 「史実では…」で「なぜ？」が生まれるか（意外性・ギャップがあるか）
- A4 貫通する謎に手がかりが正しく接続しているか
- A5 再訪・遊び直しの動機が仕込まれているか

### S-B 善悪の垣根を超えた人間理解（大目標2）

- B1 主人公が英雄化・聖人化されていないか（弱さ・迷い・したたかさが描かれているか）
- B2 敵役・脇役に人間としての厚みと「声」があるか
- B3 教訓・説教でまとめていないか（判断が子どもに残されているか）
- B4 「その時代の必然」と「現代の感覚」の差を、断罪せずに見せているか

### S-C 読者適合（小5・中1）

- C1 小5が音読できる文か（文長・語彙・リズム）
- C2 中1が読んで幼稚に感じないか（「もっと深く」に十分な深さがあるか)
- C3 前提知識なしで筋が追えるか（地理・人間関係の道しるべがあるか）

### S-D 史実の誠実さ

- D1 通説ベースで正確か（最新研究と乖離しすぎていないか）
- D2 史料の性格（成立時期・書き手の立場）に配慮した提示か
- D3 「実はよくわかっていない！」が好奇心の入口として機能しているか

## 評価の実施

- 作品データを変更したら `/eval-work` で多角評価を実行する。
- 評価結果の要約（G の pass/fail と、S の3点未満・4点未満項目）を、変更の報告（コミット報告・PR・JOURNAL）に添える。
- 人間の観察（子どもの実際の反応）が AI 採点と矛盾したら、**人間の観察が優先**。矛盾そのものをこの文書の改善材料として BACKLOG に積む。
