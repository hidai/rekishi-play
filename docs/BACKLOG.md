# BACKLOG — 開発バックログ

自律開発（`/auto-dev`）はここから着手する。上にあるものほど優先。人間は自由に並び替え・追記・削除してよい。

## 運用ルール

- **運用規則（単一ゲート原則・ハード境界）は CLAUDE.md「自律開発」節が唯一の真実**——ここには再掲しない。この文書での意味だけ: **⛔ ＝ハード境界の印。AI は実装せず、ループを止めずに次の着手可能タスクへ進む**（下ごしらえ・改訂案の提案は可）。⛔ は「人間の返事待ちでループを止める」印ではない。
- 各タスクは `- [ ]` の1項目。完了したら同じサイクルで `[x]` にし、詳細は docs/BACKLOG-done.md へ移して live は1行スタブ＋commit 参照だけにする（park した監視・微磨き followup も逐語を残さず要点1行＋git 参照に畳む）。live のバイト上限は `tests/docs-budget.test.ts` が毎サイクル強制する（超過は赤＝掃き出すまで commit 不可）。
- AI はタスク実行中に見つけた followup を「未整理」へ追記してよい（勝手に優先順位は上げない）。ただし followup は「次サイクルの AI が着手する作業項目」に限り、**人間宛の「push 前レビュー観点／実機で目視して」は各タスクに量産せず docs/REVIEW.md へ集約する**（人間が週1で読む唯一の面。ループが毎サイクル上書き集約）。
- 「観察メモ」には人間が子どもたちの生の反応を書く。ここが最優先の評価データ（VISION の役割分担）。**この節は掃除対象外**（人間の入力面）。

## 観察メモ（人間が書く。最優先の評価データ）

（例: 「四国の章で下の子が飽きた」「クイズだけ何度もやっている」）

* X(Twitter)などでの共有用に、リンクカードが出るようにして。
* 今どのアカウントで遊んでいいるのかがわかりにくい。切替方法もわかりにくい。
* 最初に名前を入力させられるのが嫌なので、必要になる（複数人で遊びたくなる）まで不要にしたい。名前を後から編集する機能も必要か。
* 顔のバリエーションがまだ少ない。漫画のキャラクターのようにちょっと大げさなぐらい特徴を誇張するなどの手法も検討してほしい
* 顎髭が頬よりも小さくて、頬がヒゲの外側にはみ出しているキャラクターがある

* 大人から以下のフィードバックをもらいました（「すでにその人物のことを知っている読者」を前提にしている、は私も強く同意します）
1. 文書戻れないのがつらい
2. 「えっ」が没入を妨げているように感じる
プレイヤーを「あなた＝歴史上の人物」として物語に入り込ませる作りなのに、本途中に「えっ」の赤枠が入り込んでくるのが感情移入を阻害するように感じます。
この解説はそれ自体は面白いのですが、「すでにその人物のことを知っている読者」を前提にしているように見えます。初めてその人物に触れる小中学生にとっては前提知識がなく、また語り手が急に「外側」から話しかけてくるため、人物への感情移入がそのたびに途切れてしまうと思います。そのために本文とはそういった知識が分けあるんだと思うんですが「えっ」の赤字で割り込んでくるので物語からの引きはがし力が強いな、と感じました。
章の終わりにまとめて提示するとか本ストーリーとは別コンテンツにするなど、より物語パートと知識パートを分けた方が良いんではないかと思いました。

* 2026-07-28（本人プレイ）**全体的に、あまり引き込まれない。引き込まれる要素をどう作り出すかが大きな課題。** そもそもどういう人物なのかを知らないと、最初から興味が無い状態なので、その人を読むモチベーションが特に無い。偏ってもいいから、ある程度の興味を引く人物像を提示する必要がある？ **この問題が解決されるまで人物追加を停止した方が良い。** つまらないストーリーは改善するまで一旦隠してもいいぐらい。（細かい表現でなく「あまり引き込まれない」という点に集中して考えてほしい。**すぐに解決策を出さず、要因を深堀りして複数の解決策を考えるアクティビティに時間をかけたい。早急な対策は避ける。**）→ 要因分解 [design/engagement.md](design/engagement.md)
